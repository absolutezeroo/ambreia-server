# RPG F3c — Chat : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Mode choisi par le propriétaire :** Claude implémente chaque tâche ; un agent relecteur passe toutes les 2 tâches (après les tâches 2 et 4), puis une relecture finale de la branche.

**Goal:** un chat de RPG à canaux (`general`, `world`, `whisper`, `system` ; `group` et `guild` prêts mais inactifs), avec liens d'objets vérifiés et débit par canal, où chaque canal, contrôle et sorte de lien est une pièce déclarée par son module.

**Architecture:**
- **Contrats** dans `Vortex.Primitives/Chat` : `IChatChannel`, `IChatRule`, `IChatLinkKind`, `IChatRouting` (le « `ChatRouting` » de la spec), et les données `ChatSend`, `ChatLine`, `ChatPlayer`, `ChatSenderState`. Les événements vont dans `Vortex.Primitives/Events/Chat`.
- **Le cœur** est `ChatPipeline` (`Vortex.Players/Chat`), un singleton. Il garde le dernier canal déclaré par clé, trie les contrôles par priorité, filtre les liens, publie les événements, puis confie la ligne au canal.
- **Le pipeline ne connaît aucun grain.** Le canal diffuse par `IChatRouting`, que `PlayerPresenceGrain` implémente : envoyer à un joueur, publier sur un flux nommé, trouver un joueur par son nom, savoir s'il est en ligne.
- **Les pièces livrées :**
  - les canaux sont dans `Vortex.Players/Chat/Channels` ;
  - les contrôles sont dans `Vortex.Players/Chat/Rules` ;
  - la sorte de lien `item` est dans `Vortex.Rpg/Chat`.
  - Chaque module les déclare par DI.
- **Le réseau :** `RpgChatSend` (entrant, 9011) passe par un handler, qui appelle `PlayerPresenceGrain.SendChatAsync`. Deux paquets sortants : `RpgChatMessage` (9010) et `RpgChatResult` (9011).

**Tech Stack:** C# .NET 10, Orleans (silo unique, flux mémoire `RoomStreamProvider`), xUnit + FluentAssertions, `FakeProxy` / `GrainActivationContext` (Vortex.Tests.Support).

**Spec:** `docs/superpowers/specs/2026-10-09-rpg-chat-design.md` (approuvée le 2026-10-09).

## Global Constraints

- **Ids réseau :**
  - entrant `RpgChatSend` = 9011 ;
  - sortants `RpgChatMessage` = 9010 et `RpgChatResult` = 9011 ;
  - dans les régions `Vortex-specific` de `Headers.cs`, avec le commentaire `// RPG (spec §3.7)`.
- **Codes de refus (chaînes sur le fil) :** `empty`, `too_long`, `rate_limited`, `not_in_zone`, `player_not_found`, `player_offline`, `not_in_group`, `not_in_guild`, `unknown_channel`, et `refused` (voir Décision 2).
- **Texte :**
  - retrait des caractères de contrôle, puis des espaces en tête et en fin ;
  - au plus 200 caractères (`ChatConfig.MaxLength`) ; rien n'est tronqué ;
  - au plus 5 liens (`ChatConfig.MaxLinks`).
- **Débit par défaut (`ChatConfig.RateLimits`, en ms) :** `general` 1000, `world` 10000, `whisper` 1000. Un canal absent de la table n'est pas limité.
- **Clés de canal :** sensibles à la casse (`General` → `unknown_channel`). `system` ne s'envoie jamais par un joueur.
- **`sentAt` :** un entier 32 bits, en secondes Unix UTC (comme la spec : « entier »).
- **Rien n'est stocké, aucun texte de chat n'est journalisé.**
- **Grains :**
  - la présence ne rappelle jamais sa room ; elle publie sur le flux de la room ;
  - le privé appelle `SendComposerAsync` et `IsOnlineAsync` de l'autre présence, deux méthodes interleavées ;
  - pas d'`await` de grains distincts en série quand ils sont indépendants (`Task.WhenAll`).
- **Conventions du dépôt :**
  - un type par fichier ;
  - le namespace suit le dossier ;
  - le code se modifie par Edit/Write ;
  - commits en français, avec des chemins explicites, sur `main` ;
  - ne jamais commiter `scripts/sql/import_reference_data.sql` ni `docs/superpowers/specs/2026-10-06-vortex-mmorpg-master-design.md`.

## Décisions de ce plan (écarts assumés à la spec)

1. **`ChatRouting` s'appelle `IChatRouting`** : c'est une interface, que la présence implémente explicitement et que les tests remplacent par `RecordingChatRouting`.
2. **Code `refused`.** Un `ChatSendingEvent` annulé répond son `CancelReason`, ou `refused` s'il n'en donne pas. La spec ne nommait pas ce code ; il s'ajoute à la liste de §10.2 pour le client.
3. **Pas de dossier `Vortex.Players/Chat/Links/`.** Aucune sorte de lien ne vit dans Players en F3c. Le filtre de liens est une étape du pipeline, rangé à côté de lui dans `Chat/`.
4. **Le registre est journalisé à sa construction** : canaux, remplacements et ordre des contrôles. Cela se produit à la première activation d'une présence, pas au démarrage de l'hôte : aucun service ne le résout plus tôt.
5. **La recherche par nom compare en minuscules (`LOWER(name)`).** Elle lit la table sans l'index unique. C'est borné par le débit du privé (1/s par joueur), et marqué `ponytail:`.
6. **Un refus au routage consomme la fenêtre de débit.** Par exemple, un privé vers un nom inconnu : le contrôle de débit passe avant le canal.
7. **Pas de test unitaire pour `ItemChatLinkKind`** : c'est une ligne (`content.Get<ItemDefinition>(id) is not null`). La preuve `chat` du driver le couvre : un id réel est gardé, un id inventé est retiré.

## Review Focus

1. **Deux joueurs qui se chuchotent au même instant.** Chacun appelle `IsOnlineAsync` de l'autre pendant son propre tour. Sans interleaving, les deux attendraient 30 s. Test : Tâche 4, `IsOnline_IsInterleaved` (l'attribut est porté, et listé dans le manifeste).
2. **Un message fait seulement de liens invalides** (`[item:faux]`) : refus `empty`, rien n'est diffusé. Test : Tâche 1, `AMessageOfInvalidLinksOnly_IsEmpty`.
3. **Un joueur qui rentre dans le monde deux fois sur la même activation** (reprise de grâce, double entrée) : un seul abonnement à `world-chat`, donc une seule copie de chaque ligne Monde. Test : Tâche 5, le driver vérifie qu'aucune seconde ligne Monde n'arrive dans les 500 ms. `JoinWorldChatAsync` est idempotent.
4. **Un privé avec le nom tapé dans une autre casse, ou entouré d'espaces** : le message arrive, et la copie de l'émetteur porte le nom canonique. Test : Tâche 2, `AWhisper_FindsTheNameWhateverItsCase`.
5. **Un canal avec une autre casse, ou jamais vu** (`General`, `SYSTEM`, `trade` non déclaré) : `unknown_channel`, rien n'est diffusé. Test : Tâche 1, `AChannelKey_IsCaseSensitive`.

```csharp
/// <summary>What the rules remember of one sender, held by its presence; each rule keeps its own part, by type.</summary>
public sealed class ChatSenderState
{
    private readonly Dictionary<Type, object> _parts = [];

    public T Get<T>() where T : class, new()
    {
        if (!_parts.TryGetValue(typeof(T), out object? part))
        {
            part = new T();
            _parts[typeof(T)] = part;
        }

        return (T)part;
    }
}
```

```csharp
// Vortex.Players/Chat/ChatLinkFilter.cs
/// <summary>
/// Links in a chat text (spec F3c §6): a [prefix:id] token of a declared kind stays when its id
/// exists, up to maxLinks, and is removed otherwise. A token of no declared kind, or malformed, is
/// plain text. The last kind declared for a prefix wins.
/// </summary>
internal sealed partial class ChatLinkFilter
{
    private readonly Dictionary<string, IChatLinkKind> _kinds = new(StringComparer.Ordinal);
    private readonly int _maxLinks;

    public ChatLinkFilter(IEnumerable<IChatLinkKind> kinds, int maxLinks)
    {
        foreach (IChatLinkKind kind in kinds)
        {
            _kinds[kind.Prefix] = kind;
        }

        _maxLinks = maxLinks;
    }

    public async ValueTask<string> FilterAsync(string text, CancellationToken ct)
    {
        StringBuilder kept = new();
        int at = 0;
        int links = 0;

        foreach (Match token in Token().Matches(text))
        {
            if (!_kinds.TryGetValue(token.Groups[1].Value, out IChatLinkKind? kind))
            {
                continue;
            }

            kept.Append(text, at, token.Index - at);
            at = token.Index + token.Length;

            if (links < _maxLinks && await kind.ExistsAsync(token.Groups[2].Value, ct))
            {
                kept.Append(token.Value);
                links++;
            }
        }

        return kept.Append(text, at, text.Length - at).ToString();
    }

    [GeneratedRegex(@"\[([a-z]+):([^\[\]\s]+)\]")]
    private static partial Regex Token();
}
```

```csharp
public async Task<PlayerId?> GetPlayerIdByNameAsync(string name, CancellationToken ct)
{
    string lowered = name.Trim().ToLowerInvariant();

    if (lowered.Length == 0)
    {
        return null;
    }

    KeyValuePair<int, string> found;

    try
    {
        await using VortexDbContext dbCtx = await _dbCtxFactory.CreateDbContextAsync(ct);

        // ponytail: LOWER(name) reads past the unique index on players.name, one scan per whisper
        // that the whisper rate limit bounds; a case-insensitive indexed lookup if players grow.
        found = await dbCtx
            .Players.AsNoTracking()
            .Where(x => x.Name.ToLower() == lowered)

            .FirstOrDefaultAsync(ct);
    }

        _logger.LogError(ex, "Failed to resolve a player by name.");

        throw;
    }

    // No row: the default pair, id 0.

        return null;
    }

    SetNameCache(found.Key, found.Value);
```

```csharp
internal sealed partial class PlayerPresenceGrain : IChatRouting
{
    private readonly ChatPipeline _chat;
    private readonly ChatSenderState _chatState = new();
    private StreamSubscriptionHandle<RoomOutbound>? _worldChatSub;

    public async Task SendChatAsync(string channel, string target, string text, CancellationToken ct)
    {
        // Only a player in the world writes: its socket is attached.
        if (_sessionObserver is null)
        {
            return;
        }

        string? refusal;

        try
        {
            string name = await _grainFactory.GetPlayerDirectoryGrain().GetPlayerNameAsync(PlayerId, ct);

            refusal = await _chat.SendAsync(
                new ChatSend(PlayerId, name, channel, target, text, _chat.Time.GetUtcNow()),
                _chatState,
                this,
                ct
            );
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            _logger.LogWarning(ex, "The chat message of player {PlayerId} failed.", PlayerId.Value);

            return;
        }

        if (refusal is not null)
        {
            await SendComposerAsync(new RpgChatResultMessageComposer { Channel = channel, Code = refusal });
        }
    }

    public Task SendSystemChatAsync(string text, CancellationToken ct) => _chat.SendSystemAsync(text, this, ct);

    PlayerId IChatRouting.Sender => PlayerId;

    RoomId? IChatRouting.Room => _state.ActiveRoomId.Value > 0 ? _state.ActiveRoomId : null;

    Task IChatRouting.SendToPlayerAsync(PlayerId to, ChatLine line)
    {
        RpgChatMessageComposer composer = ToComposer(line);

        // Oneself through the own queue, not through a grain call behind this very turn.
        return to == PlayerId
            ? SendComposerAsync(composer)
            : _grainFactory.GetPlayerPresenceGrain(to).SendComposerAsync(composer);
    }

    Task IChatRouting.PublishAsync(string stream, long key, ChatLine line) =>
        this.GetStreamProvider(OrleansStreamProviders.ROOM_STREAM_PROVIDER)
            .GetStream<RoomOutbound>(StreamId.Create(stream, key))
            .OnNextAsync(new RoomOutbound { RoomId = new RoomId((int)key), Composer = ToComposer(line) });

    async Task<ChatPlayer?> IChatRouting.FindPlayerAsync(string name, CancellationToken ct)
    {
        IPlayerDirectoryGrain directory = _grainFactory.GetPlayerDirectoryGrain();

        return await directory.GetPlayerIdByNameAsync(name, ct) is { } id
            ? new ChatPlayer(id, await directory.GetPlayerNameAsync(id, ct))
            : null;
    }

    Task<bool> IChatRouting.IsOnlineAsync(PlayerId player, CancellationToken ct) =>
        player == PlayerId
            ? Task.FromResult(_sessionObserver is not null)
            : _grainFactory.GetPlayerPresenceGrain(player).IsOnlineAsync(ct);

    /// <summary>Listens to the World channel (spec F3c §4), once per activation: a resume or a
    /// second entry does not double it. Its failure costs the World channel only, never the sign-in.</summary>
    private async Task JoinWorldChatAsync()
    {
        if (_worldChatSub is not null)
        {
            return;
        }

        try
        {
            _worldChatSub = await this.GetStreamProvider(OrleansStreamProviders.ROOM_STREAM_PROVIDER)
                .GetStream<RoomOutbound>(StreamId.Create(OrleansStreamNames.WORLD_CHAT_STREAM, 0L))
                .SubscribeAsync(this);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Player {PlayerId} could not join the world chat.", PlayerId.Value);
        }
    }

    private async Task LeaveWorldChatAsync()
    {
        if (_worldChatSub is null)
        {
            return;
        }

        try
        {
            await _worldChatSub.UnsubscribeAsync();
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Player {PlayerId} could not leave the world chat.", PlayerId.Value);
        }

        _worldChatSub = null;
    }
```
